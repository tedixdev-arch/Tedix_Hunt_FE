# F7-FE-04 — Immutable save and reopen

Reuses POST /api/creator/templates/{key}/versions {content} and owner GET detail. Explicit save only; no request per keystroke. Universal saves preflight current owner detail, require matching version/status/content, then send complete next immutable snapshot. Backend version checks remain the final race boundary. Conflicts or uncertain save responses preserve input and require explicit reopen/discard before retry. Submitted content is locked; C5 allows approved Universal and changes-requested candidates to save new drafts. No client approval/publication/provenance metadata is sent.

All persisted working fields hydrate from successful responses. Missing optional fields, arbitrary supported story/gameplay/scoring/configuration and terminal entries survive unchanged round trips. Stale detail reads cannot restore an earlier route; authoring controls are disabled during mutation. Failed requests preserve working input and prior snapshot.

Focused: 43 Vitest tests passed across persistence, creation and Signal. Includes unchanged no-op, exact immutable next version, canonical server response, stale preflight/reopen, 400/403/409/500 retention, submitted lock, approved/correction draft and 401/403/404 ownership denial. Integration/deployment remain unverified.
