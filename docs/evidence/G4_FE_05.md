# G4-FE-05 — Independent manual locality review

Locality proposals use the same Admin workspace category filter. GET returns pending proposals only; selected facts/evidence/coordinates and administrative context remain read-only. Existing country-scoped registry search presents possible duplicates without creating or merging records. A human approves/rejects with a 10–1,000 character reason as required by the actual route. Self-review is denied for both decisions, including combined roles. A fresh pending read detects concurrent decisions; duplicate 409 refreshes and leaves the proposal pending. Only returned decisions/reasons/approved locality IDs are displayed. Template approval is separate.

Validation: eight rendered proposal cases cover approve, reject, required reason, duplicate-pending, independent/self-review, concurrency, 401/403 and empty/error recovery. API tests capture exact private routes and narrow bodies. The batch also hardens revoked-access clearing, refreshes retained authority after candidate decisions, adapts existing Admin/Signal map tests to the shared workspace, and collapses the existing sidebar at narrow widths. Full validation and evidence boundaries: [batch report](../G4_FE_01_05_Implementation_Report.md).
