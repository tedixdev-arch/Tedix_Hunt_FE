# Personal Challenge LaTeX implementation report

- **Library:** KaTeX 0.19.1, bundled locally with its CSS/fonts. No Tedix code or dependencies. Mixed strings use `$...$` inline and `$$...$$` display delimiters. Ordinary text stays React-escaped. Only generated KaTeX markup enters HTML; trust-required commands are rejected, strict parsing is enabled, and expansion/size limits bound rendering. Errors show the original expression with correction guidance. Incomplete delimiters stay literal while typing.
- **Fields:** title, instructions/question, matching cards, choices, blank prompts, recall cards, drag items/targets, sequence elements, construction pieces/slots, mistake steps/corrections, shape labels, rule descriptions, hints, feedback and solutions. String accepted answers can be previewed but retain exact existing text/case validation. Numeric fields remain numeric.
- **Creator coverage:** Complex / LaTeX retains the existing guided structure, navigation and add/remove/reorder controls. Edit with Preview stays first/default. Shared pencil fields render as you type; raw structured inputs have a formula companion. Shared authored and legacy playable renderers support the applicable mathematical content. Native selects retain literal option text with rendered formula companions, since option elements cannot contain mathematical markup.
- **Participant coverage:** not available for arbitrary saved Personal Challenges in this FE. `src/features/creator/ParticipantPreview.tsx` explicitly shows a manual simulation/configuration inspector. The student `CheckpointChallenge` uses static `eventData.challenge`, not saved custom exercises. Neither path consumes these exercises. This PR does not invent a participant integration or claim compatibility from Creator tests; when a real custom-exercise participant route is added it should reuse the shared renderer.
- **Compatibility/limitations:** no schema, backend, scoring or answer-validation changes. Source strings/delimiters survive the existing persistence adapter and JSON round trips. All 15 canonical types remain supported. Existing field lengths and plain-text contract still apply; in particular text matching `<` followed by a letter is rejected by the existing contract (use `\\lt` in formulas). Existing numeric answer/range/pattern fields cannot contain LaTeX. Presentation does not provide symbolic equivalence evaluation. Literal paired dollars are interpreted as formulas; escape dollars with a backslash to keep them literal. Unmatched delimiters display literally. HTML and KaTeX trust-required extensions are unsupported.
- **Verification:** `npm run typecheck` passed; `npm run build` passed (bundle-size warning). Node suite: 42/42 passed. Full Vitest suite with `--maxWorkers=2`: 832/832 tests, 39 files passed. Default full-suite Vitest invocation was stopped and rerun with bounded workers. New tests cover mixed/inline/display math, matrices/integrals/roots/Greek/subscripts, malformed and unsafe commands, ordinary strings/numbers, all 15 types, JSON save/reopen, mode preservation, live structured editing and ID-based matching correctness. Chromium smoke check passed at 1280, 390 and 320px: formulas rendered, modes switched, no page overflow or runtime errors. No backend save request or participant compatibility claim is based on these local tests.
